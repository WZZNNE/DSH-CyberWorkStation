# 使用与运维说明

版本 0.1　设计日期：2026 年 9 月 15 日

> **这是拟议产品的使用说明。** 下文的页面名称、按钮、提示和流程用于指导实现与验收，尚未作为完整服务安装运行。本包已有内容和验证范围以交付清单为准；现有 DSH 的实际能力见[本地接入审查](research/local-integration.md)。本文不提供尚未存在的安装命令。

## 1 这个服务帮助你做什么

服务保存项目中的明确要求、决定、偏好和可核验的工作状态，在新任务开始时提供当前适用的内容。你可以看到它记住了什么、来自哪里、何时生效，以及哪些任务正在使用。

“请用中文回答”属于偏好，“本项目不调用付费 API”属于约束，“尝试过方案 A，测试失败”属于有来源的工作记录。系统应把它们分开，避免把讨论中的设想变成强制要求，或把计划当成完成结果。

你通常只需说清内容和适用项目。标签、索引和存储版本由服务管理，高级详情提供给需要排查的人。

## 2 首次使用：关联项目和数据偏好

### 2.1 关联当前项目

拟议首次使用页显示当前账户、服务位置和宿主识别出的项目。确认项目名称后，服务分配稳定的项目身份；日后目录移动或容器路径改变，应关联同一个项目，而不是再建一份记忆。

示例：宿主路径为 `H:/Shop`，容器路径为 `/workspace/shop`。只要它们在可信项目配置中指向同一个项目，就能共享项目记忆。服务不会仅因文件夹都叫 shop 就自动合并。

已有项目可通过“关联现有项目”选择；复制代码创建独立项目时，默认只复制明确选择的记忆，不自动继承全部历史。分支规则和一次性任务例外会单独显示适用范围。

“我的全局记忆”表示当前用户在其获准项目中的通用偏好，不表示其他用户或所有 agent 都可以读。角色和组织授权仍然适用。

### 2.2 选择数据传输偏好

记忆存在哪里与模型在哪里处理是两件事。即使数据库在本机，云端提取器、向量模型、重排模型或主任务模型仍可能收到内容。拟议设置页分别列出以下路径：

| 偏好 | 使用效果 |
|---|---|
| 全程本地 | 原文、记忆和查询只交给已配置的本地服务与本地模型；缺少本地模型时保留手工编辑和关键词检索 |
| 指定步骤可用云端 | 逐项启用事实提取、向量生成、结果筛选或主任务模型；显示接收服务及发送内容类别 |
| 使用远程记忆服务 | 数据库与相关备份位于指定远程服务；模型处理设置仍单独配置 |

默认采用本地优先。已经配置云端主模型时，界面必须说明“送入任务上下文的记忆将随请求发送到该模型”。仅关闭云端 embedding 不等于所有内容都留在本地。

偏好变更会约束后续发送，不能收回已经发送给其他服务的数据。无法满足当前传输偏好时，系统应停止相应处理并说明原因，不能自动换成另一个云端供应商。

### 2.3 完成第一次验证

用一条非敏感、容易辨认的要求开始，例如“本测试项目的文档采用中文”。确认页面出现该要求、来源和范围；新建一个同项目任务，检查“本任务正在使用”中是否出现它。随后撤销该要求，再创建任务，确认它不再作为当前约束出现。

这一流程验证最基本的保存、跨任务读取和撤销；不能证明全部语义理解与外部动作限制都正确。

## 3 日常界面

拟议导航保持七个入口：

- **项目记忆**：当前项目可用的事实、决定、偏好和工作记录。
- **要求与例外**：必须遵守的要求、例外条件、生效时间和未解决冲突。
- **待确认**：指代不明、来源不足或互相矛盾的提案。
- **最近变更**：新增、修改、撤销以及变更人的时间线。
- **任务正在使用**：任务的适用要求、相关背景、来源及刷新状态。
- **删除进度**：停止使用、在线清理和备份处理分别到了哪一步。
- **服务状态**：保存、提取、检索、索引、连接和备份是否正常。

每条记录默认只显示“记住了什么、在哪里适用、何时生效、来源、状态”。展开来源后才显示原始消息或工具证据。向量分数不作为正确性提示；更有用的说明是“来自你 9 月 15 日的明确要求，只适用于生产环境”。

### 当前与历史怎么区分

默认查看当前适用内容。历史视图可以选择某个日期，并分开查看“系统当时记录的内容”和“现在认为当时有效的内容”。未来生效的要求列在“即将生效”，不会提前替换当前要求。

撤销、被替代和纠错记录在历史中保留关系；彻底删除后的正文不能通过历史模式重新取回。没有权限阅读来源时，界面只显示允许披露的来源摘要或“来源不可查看”，不越权展开原文。

## 4 怎样口头新增和修改要求

### 4.1 明确新增

你说：“这个项目的接口字段统一使用 snake_case。”

拟议系统保存为项目约束，并简短回显：“已记住：本项目接口字段使用 snake_case。”不要求你填写类型或标签。若“这个项目”已经由任务身份确定，无需重复询问。

你说：“也许应该改成 camelCase。”

它应进入讨论或假设，不能直接替换已有要求。待你明确决定后，再形成新的变更。

### 4.2 条件和一次性例外

你说：“生产环境禁止付费 API；这次演示允许用一次。”

页面应显示一条生产要求和一条指向它的任务例外。例外的任务范围、截止条件必须可见；下一个生产任务不能继承演示许可。若“一次”无法对应明确调用或任务边界，系统在相关动作前用具体候选澄清。

条件属于要求的一部分。检索到“可以使用”时必须一并显示“仅此演示任务”，不能把前后句拆开导致许可扩大。

### 4.3 未来生效

你说：“10 月 1 日起允许付费 API。”

界面用当前设置的时区展示完整生效日期，保留原始表达。生效前旧要求仍有效；到达时间边界后，新任务和新动作使用新要求。依赖旧要求的任务需刷新，不能因为没有新增消息就一直沿用旧许可。

“月底”“明年”“发布以后”需要明确的时间或事件依据。依据不清且会改变当前动作时进入待确认；普通背景可以继续保存，相关动作等待规则明确。

### 4.4 撤销、替换、纠错与彻底删除

| 你的表达或操作 | 服务应该做什么 |
|---|---|
| 不再要求必须使用 MySQL | 撤销“必须使用”，不生成“禁止使用”，也不自动创建迁移任务 |
| 把必须使用 MySQL 改成 PostgreSQL | 替换要求，关联旧要求并处理生效时间 |
| 上次记错了，我说的是测试环境 | 纠正记忆与适用范围，保留必要的变更关系 |
| 暂时不用显示这些旧讨论 | 归档普通背景；有效约束仍保持约束力 |
| 把这段信息从记忆彻底删除 | 启动删除作业，列出原文、派生记忆、索引、缓存及备份范围 |

“删除这条要求”可能表示解除要求，也可能表示不再保留文本。拟议界面提供“停止作为要求”和“彻底删除内容”两个具体选项，不用技术术语让用户猜。

目标明确且已授权的可逆变更直接执行并提供撤销入口。只有对象不清、影响范围有实质歧义或发生版本冲突时才要求选择，避免每次记忆写入都弹确认。

## 5 人工编辑、冲突和防止旧内容复活

在记录上选择“编辑”，修改内容、范围、条件或生效日期后保存。系统会记录编辑者和新版本，并展示受影响任务；常规编辑无需让用户理解版本号。

如果你打开编辑框后另一个 agent 已修改同一记录，系统不能覆盖对方的新内容。拟议冲突页并列显示“你打开时”“当前内容”“你的修改”，提供重新编辑或明确合并。未获准读取的修改不能通过差异页泄漏。

撤销编辑也会生成新变更。若期间已有其他变更，“撤销”需要重新核对当前版本，不能盲目回退整份数据库。

旧对话、旧摘要或旧备份可能包含已撤销要求。导入与重新提取必须遵守现有撤销和删除记录；只因再次看到相同旧文字，不会重新启用它。你明确说“恢复之前那条要求”时，系统可以创建新的启用事件并显示来源。

Markdown 和 JSON 可以导出、离线编辑后导入，但它们是编辑交换文件。文件变更先生成可检查的差异和版本化变更，不能让数据库和文件长期同时成为可独立覆盖的权威来源。

## 6 agent 可以读哪些内容

任务页面显示“可读取范围”，例如当前用户的全局偏好、当前项目共享接口与后端记录。这里的“全局”仍受任务授权约束；它不会因模型填写 global 标签而自动开放。

前端/后端等标签帮助检索相关内容，授权由可信宿主与服务端策略决定。协作任务需要额外资料时，可以提交具体请求，说明需要什么以及用于什么工作；是否开放由已有规则或有权限的用户决定，不靠另一个模型自由裁决。

子任务默认继承经收窄的范围。父任务结束、授权撤销或租约到期后，子任务需要重新校验，不能继续使用复制来的长期凭证。

“任务正在使用”区分三种情况：已准备上下文、已交给模型、等待刷新。检索到内容不等于模型实际看过；已交给模型也不等于它遵守了要求。可由工具入口强制执行的限制显示为“操作受控”，风格等自然语言要求显示为“依赖模型与结果检查”。

## 7 中断后如何继续任务

恢复页面展示最近已确认保存的位置、目标、当前要求、已验证结果、待办与需要核实的动作。你选择继续后，宿主先更新权限和当前约束，再恢复工作。

以下状态必须分开：

1. **计划中**：agent 打算执行，还没有开始。
2. **已开始**：动作已发出，但尚无可靠完成证据。
3. **已确认完成**：有工具结果或环境检查作为证据。
4. **结果待核实**：程序中断，外部操作可能已发生。

例如部署请求发出后程序崩溃，恢复不能因为缺少成功日志就再次部署。应先查询部署状态；无法自动核实的操作明确列出，再决定后续处理。文件写入也应检查实际文件与预期结果。

服务只能恢复已确认持久化的事件。尚未发送或尚未提交的最后一段文字不能宣称已保存。恢复后的旧进程若迟到提交，服务应拒绝它过期的任务身份，防止两个执行者同时接管。

## 8 降级行为与故障处理

普通背景检索允许有限降级；当前权限和关键操作约束无法确认时，受控动作等待恢复。提示应该说明受影响能力，避免一个“记忆不可用”覆盖所有情况。

| 状态或现象 | 拟议行为 | 用户/运维处理 |
|---|---|---|
| 向量模型离线 | 使用关键词和结构字段检索，显示语义检索暂不可用 | 可以继续一般查询；重要背景不足时展开来源或调整关键词 |
| 提取模型离线 | 原始事件先持久保存；手工记录与明确结构化操作继续；含糊的新规则待处理 | 查看“已保存、待整理”；相关关键动作不会误把这当作规则已生效 |
| 索引更新中断 | SQL 仍为权威；增量/全文路径补入新记录；后台重试 | 查看积压和最后完成时间；不反复重新导入数据 |
| 主记忆服务失联 | 普通任务按既定离线策略处理；无法验证权限或约束的动作暂停 | 恢复连接后刷新任务；不能静默换到过期备份 |
| 保存请求超时 | 显示“结果待确认”，用同一操作身份查询/重试 | 避免连续新建相同操作；确认提交结果后再继续 |
| 磁盘满或写权限失败 | 拒绝新写入，已读内容不伪装为已更新 | 腾出空间或修复目录权限，再重试原操作 |
| 版本冲突 | 保留用户草稿，展示差异 | 重新编辑或明确合并 |
| 要求已撤销但任务未刷新 | 标注任务待刷新，拒绝依赖旧要求的新受控动作 | 刷新或重建上下文；已开始动作单独处理 |
| 数据库损坏 | 停止写入并隔离故障文件，进入恢复流程 | 从一致性备份恢复，先核对删除清单再开放查询 |
| 任务要求过多 | 说明哪些范围使预算不足，建议拆分任务 | 缩小当前工作范围；不通过关闭禁止项来凑预算 |

提取器重试必须检查来源版本；如果原始消息已编辑或删除，迟到的结果不得重新写成有效记忆。更换向量模型后独立重建索引，完成前继续可靠的旧代际或关键词路径，不能混合不兼容向量。

## 9 备份、恢复与删除进度

### 9.1 备份

拟议备份包包含一致性的权威数据库、必要载荷、版本和迁移信息；索引可以重建，不要求每次完整复制。设置页展示保留周期、上次成功备份和恢复验证日期。

运行中的数据库应通过受支持的一致性备份接口处理。不要直接复制其中一个正在变化的数据库文件并把它称为完整备份；相关日志和载荷可能尚未一致。

### 9.2 恢复

恢复在隔离位置进行：校验备份、匹配版本、取得不早于删除请求的最新删除清单、应用删除与撤销信息、核验引用，再开放查询。已删除内容在恢复过程中也不能短暂暴露给模型。

如果只能找到很旧的备份，且无法取得最新删除清单，恢复状态应显示“无法确认删除记录完整”。服务不得自动向 agent 开放这份数据；应补齐清单或明确采用仅恢复可验证项目的流程。

恢复也不能覆盖备份产生以后仍存在的有效新事件。导入器按事件与版本去重，保留后续人工修改和撤销关系；“恢复旧版本”不是无条件替换当前整个记忆库。

### 9.3 彻底删除

拟议删除页分三层报告：

- **停止使用**：当前、历史和模型检索已经隐藏目标内容。
- **在线副本清理**：服务控制的正文、原始证据、派生摘要、全文/向量索引、缓存等已处理。
- **备份处理**：旧备份已清除，或会在显示的保留期限结束后失效；恢复流程持续应用删除清单。

删除清单保留执行恢复过滤所需的不透明标识、序号和状态，不保存已删除正文。它也必须受保护和备份，避免删除记录本身丢失造成复活。

用户下载到其他位置的导出文件、其他模型供应商保存的内容，以及宿主尚无删除接口的原始会话日志，都不能直接纳入本服务的完成保证。当前 DSH 原日志采用受版本管理的追加式记录；未来适配器若不能清理某类副本，页面必须逐项显示“尚未清理/不在控制范围”，不能靠删除记忆条目就宣布全部永久删除。

## 10 运维检查与术语

日常关注保存错误、待整理积压、索引延迟、撤销待刷新任务、租约冲突、删除作业和备份状态。告警只在有可操作问题时出现，普通用户无需持续查看技术计数器。

故障报告可导出不含正文和凭据的诊断信息：软件版本、操作 ID、时间、错误类别、积压数量及检查结果。开启正文调试应是有期限的显式选择，默认不把记忆全文写入诊断日志。

| 术语 | 用户可以怎样理解 |
|---|---|
| 当前有效 | 在这个项目、任务和时间里适用 |
| 来源 | 谁在哪条消息或哪个可验证结果里表达了这件事 |
| 条件/例外 | 要求什么时候适用、哪些明确情况可以不同 |
| 版本冲突 | 你开始编辑后，别人也修改了同一内容 |
| 任务快照/上下文收据 | 这次任务被提供了哪些内容与版本的记录 |
| 租约 | 某个任务执行者暂时获准继续工作的有效期 |
| 索引 | 为查找内容建立的辅助目录，坏了可以重建 |
| 撤销 | 要求不再适用，历史关系仍可保留 |
| 彻底删除 | 停止读取，并按明确范围清理正文和相关副本 |
| 检查点 | 已确认保存的工作状态，恢复仍要核验当前规则和实际结果 |

本包实际运行的参考验证及命令由交付清单统一记录。完整产品投入使用前，还须完成身份授权、宿主接入、恢复演练、删除范围验证和真实用户操作测试；不能把设计中的页面与保证误认为已经交付。
