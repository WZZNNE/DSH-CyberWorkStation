## 00 · 这是什么

**DSH CyberWorkStation** 把 [DeepSeek Harness（dsh）](https://github.com/deepseek-ai/deepseek-harness) 从"命令行工具 + 朴素 Web UI"变成一台可视化工作站。它由一个桌面启动器和 22 个插件组成：

- **DSH 启动器**：双击 EXE 打开的管理面板，13 个页面——一键启动 / 退出、插件与 Skill 市场、会话与存储、更新与自检、Tokens 统计、控制甲板、模型参数、凭据中心、记忆与上下文、皮肤、日志。
- **dsh 本体里的面板**：22 个插件把功能直接做进 dsh 的页面——设置里多出凭据中心、模型清单同步、联网搜索、多媒体 API、桌宠、用量与费用；对话里多出消息编辑、临时对话、拖文件、思考档位……

「本体」指内置在 `core/` 里的上游 deepseek-harness，一行未改，随时可以整体升级到任意上游版本。

### 特点

- **不改本体。** 所有能力都是外挂的插件和独立程序，升级本体不会丢功能。
- **图形化。** 以前要改 `settings.yaml`、敲 `dsh plugin` 命令的事，现在都在页面上点几下；配置改完 1.5 秒内生效，不用重启。
- **密钥有归处。** API Key 只进 dsh 的凭据库（装了钥匙串插件就进 Windows 凭据管理器），不写进配置文件；所有面板只能从本机访问。
- **能复用就复用。** 22 个套件插件里 19 个原创、3 个二次开发；另有 9 个社区插件原样采纳，全部列在「插件清单」里。

### 组成一览

| DSH 启动器 | 13 个页面 · 中英双语 · 3 款皮肤 | `launcher/`，双击 `DSH启动器.exe`；本体约 1.5 秒启动 |
| 套件插件 | 22 个（原创 19 · 二改 3） | `plugins/`，安装时自动注册 |
| 社区插件 | 9 个 + 1 个 MCP 记忆服务器 | 在启动器插件市场里装，不进仓库 |

### 快速开始

前置：Windows 10/11、Git、Node.js `^22.19 || >=24`（推荐 24 LTS）、Edge 或 Chrome。

```bat
git clone https://github.com/WZZNNE/DSH-CyberWorkStation.git
cd DSH-CyberWorkStation
setup.cmd
```

`setup.cmd` 会安装依赖、构建本体（首次约 5–10 分钟）、注册全部套件插件和 Skill，然后打开启动器。之后每次使用双击 `launcher/DSH启动器.exe` 即可。API Key 在启动器「凭据中心」页或 dsh 设置 → 凭据中心 里填。

## 01 · DSH 启动器：13 个页面

启动器是一个独立的小程序：双击 `DSH启动器.exe`，它以无地址栏的应用窗口打开 `http://127.0.0.1:3090`。只监听本机，页面自带访问令牌。左下角「中 → EN」一键切换中英文。

截图时本体处于 OFFLINE 状态，所以需要 dsh 在线才能读取的页面（模型参数、凭据中心、记忆与上下文）显示的是占位提示；在线后能看到什么，在各图说明里补充。

### 图 01 · 仪表盘

![仪表盘](docs/screenshots/2026-09/01-launcher-dashboard.webp)

**功能**

顶部横幅显示运行状态（OFFLINE / RUNNING）；四张卡片是本体版本、Node 版本、默认模型（旁边直接链到凭据中心去改）和「打开 WEB UI」。「文件夹」一栏输入绝对路径就能新建工作区；下面四张快捷卡分别打开本体仓库、`~/.dsh` 主目录、插件目录和会话日志目录。中间的控制台实时滚动本体的输出。右下角是「一键启动」和「退出」。

**我们做了什么**

- 一键启动约 1.5 秒（本体已构建时），启动后自动可用；未构建时自动回退到源码方式启动。
- 退出只停 dsh 自己的进程，不会误杀其它终端或程序；重复点击不会启动第二份。
- 「新建工作区」输入路径即建，刷新 dsh 页面就能选用（本体自带的「+」按钮对未分组会话是无效的）。

> **图里没体现的** 「一键启动」在皮肤里带电流特效，RUNNING 状态是翻牌动画；`#deck` 这类地址深链可以直接打开对应页面。

### 图 02 · 插件管理

![插件管理](docs/screenshots/2026-09/02-launcher-plugins.webp)

**功能**

上方输入 npm 包名或 `link:` 本地路径一键安装；表格列出 web profile 里的每个插件：版本、来源（npm / link）、是否作为 bundle 层挂载，以及「卸载」。社区插件和套件插件混排在同一张表里。表格下方是「插件市场」（搜 npm 一键安装）和「内置组合行」（本体自带的一百多行只读挂载清单）。

**我们做了什么**

- 安装、卸载、市场安装、一键更新都走本体自己的插件命令，和命令行操作完全等价。
- 两个被 profile 补丁引用的插件（凭据钥匙串、LAN 防线）卸载前会被拦住，并给出迁移步骤，避免下次启动加载不存在的模块。
- 插件市场按 dsh 生态过滤 npm 结果；皮肤包不会混进插件列表（另有皮肤市场）。

> **图里没体现的** 9 个社区插件就是从这一页装的。`dsh-context` 需要 0.40 以上版本，自检会点名过旧的版本。

### 图 03 · Skill 管理

![Skill 管理](docs/screenshots/2026-09/03-launcher-skills.webp)

**功能**

列出两处 Skill：用户目录 `~/.dsh/skills` 里的（套件随安装放进去的 `control-deck-authoring`、`desktop-pet`、`skin-studio`）和本体源码自带的 11 个开发规程。每行显示来源与描述。下方「Skill 市场」按关键词搜 GitHub 仓库，一键下载解压到用户目录。

**我们做了什么**

- 三个 dsh 内 Skill 都是原创：皮肤工坊（让模型做皮肤）、控制甲板编写（让模型帮你写提示词 / 正则 / 世界书，或迁移 SillyTavern 资产）、桌宠制作（从人设到素材清单）。
- 仓库另有 7 个给 Claude Code 用的工程 Skill，不出现在这一页，见「Skill 清单」。

### 图 04 · 对话管理

![对话管理](docs/screenshots/2026-09/04-launcher-sessions.webp)

**功能**

`~/.dsh/sessions` 下的全部会话按工作目录分组（最新在前，组头显示数量与最近时间），可按工作区 / 会话 id 过滤，「打开会话文件夹」直达资源管理器，展开一组能对单个会话「导出 ZIP」（需要 dsh 在线）。组名前的「≈」表示目录是尽力推断的。

**我们做了什么**

- 这一页是只读的：没有删除按钮，删会话请在资源管理器里做。
- 截图里 `tmp\2026…` 那些目录是「临时对话」插件为每次临时会话建的草稿目录。

### 图 05 · 存储空间

![存储空间](docs/screenshots/2026-09/05-launcher-storage.webp)

**功能**

上表统计 9 个关键目录（本体仓库、`~/.dsh`、会话、存储、profile、插件、用户 Skill、启动器、node_modules）的占用，每行可一键打开。下面的**配置备份**把套件在 `~/.dsh` 下的配置打成一个 JSON：`settings.yaml`、控制甲板与预设、联网搜索、安全规则、模型参数、记忆库、profile 补丁、Skill、hooks、前端皮肤；「预览内容」先列出文件再确认；「导入恢复」前会把现有文件另存一份。

**我们做了什么**

- 备份不包含密钥文件和会话日志；恢复只接受白名单内的文件，越界或超限的包会被拒绝，并标出哪些文件需要重启 dsh 才生效。
- 恢复的记忆库在 dsh 运行中也会被合并进来。

### 图 06 · 更新推送

![更新推送](docs/screenshots/2026-09/06-launcher-update.webp)

**功能**

左上「版本」卡对比本地本体与上游最新版本（有新版本时标出），三种更新方式：一键更新本体（git pull + 构建）、升级到上游最新 tag、升级到指定 tag。右上「插件」一键更新 profile 里的全部插件。中间的**启动器自检**八项：Node 版本、pnpm、端口、本体检出、插件 peer 链接、配置文件、内置 CLI 是否已构建、web profile 已注册的插件。下方实时滚动更新输出。

**我们做了什么**

- 「升级到 tag」可以把本体整体换成任意上游版本并重新构建；因为本体零改动，随时可做，套件功能不受影响。
- 自检的插件名单读自 `plugins/` 目录，新插件落地即被检查；过旧的社区插件会被点名。

### 图 07 · Tokens 统计

![Tokens 统计](docs/screenshots/2026-09/07-launcher-tokens.webp)

**功能**

Claude Code 风格的用量总览：Overview / Models 两个分页，All / 30d / 7d 时间窗；八张卡片——会话数、消息数、总 tokens、活跃天数、当前与最长连续天数、最忙的一天、最常用模型；26 周热力图；下方按日明细列出每天的调用数、缓存命中 / 未命中、输出与费用。

**我们做了什么**

- 数据来自费用插件的账本，启动器只读不另记一份。
- 本地模型免费：回环地址的路由只有命名了付费厂商且带该厂商凭据时才计费。
- Models 分页按模型拆分 tokens 与费用。

### 图 08 · 控制甲板

![控制甲板](docs/screenshots/2026-09/08-launcher-control-deck.webp)

**功能**

SillyTavern 级的提示词工程台。顶栏：**预设**（保存 / 载入 / 删除）和**导入 / 导出**（整份甲板，或 SillyTavern 的世界书 / 正则脚本 / 提示词预设 JSON）。七个分页：**提示词**（多条分级注入，支持 `{{date}}`、`{{model}}`、`{{random:a,b}}` 等宏，可设间隔）、**正则脚本**（作用于用户输入 / 世界书 / AI 输出显示）、**世界书**（关键词命中就注入设定，全套 SillyTavern 字段）、**采样与上下文**（温度 / 最大输出 / 停止词总开关；工具禁用清单）、**联网搜索**、**安全规则**、**上手指南**。页底一个「保存并热载」写全部分页，1.5 秒内生效。

**我们做了什么**

- 注入不改写你的原话：提示词与命中的世界书作为单独一条上下文放在你的消息之后。
- 字段与 SillyTavern 同名同义，老用户零学习成本；ST 的世界书、正则、提示词预设 JSON 可直接导入导出。
- 写坏的正则不会拖垮 dsh：规则在独立线程里跑，超时的会被停用并在状态行点名。
- 正在编辑的内容不会被预设加载或导入的晚回复覆盖；保存失败保留草稿。

> **图里没体现的** 联网搜索与安全规则分页的内容见 dsh 设置里的对应截图（两边写的是同一份配置）。字段速查在 `control-deck-authoring` Skill 里，可以直接让模型替你写。

### 图 09 · 模型参数

![模型参数](docs/screenshots/2026-09/09-launcher-model-params.webp)

**功能**

给任意模型设上下文上限（`contextWindow`）与最大输出（`maxTokens`），能改档位的路由还可设**思考档位**；本地模型（LM Studio / Ollama）可以探测后端、自动写入推荐档位，之后直接在 dsh 的模型选择器里选。工具栏：「探测 LM Studio / Ollama」「刷新」「自动为未声明档位的本地模型写入推荐档位」、按模型 id 过滤。截图时 dsh 未运行，列表为空。

**我们做了什么**

- 在线时列出每条路由（DeepSeek 官方、OpenRouter、本地）的每个模型及当前生效值，每行单独保存。
- 本地模型按家族自动教会档位；只有开 / 关思考的模型（如 Qwen3）选 Off 时会自动附加 `/no_think`。这就是「dsh 默认 262,144 而本地只装了 8k」冲突的解法。
- OpenRouter 路由每行可一键加 / 删 `:online` 联网变体。
- 保存一行不会丢其它行的草稿。

### 图 10 · 凭据中心

![凭据中心](docs/screenshots/2026-09/10-launcher-credentials.webp)

**功能**

在线时列出**每一个 API 凭据引用**（如 `OPENROUTER_API_KEY`）：是否已配置、存在哪里、绑定在哪些功能上（模型路由、多媒体、联网搜索、桌宠、记忆向量）、别名与备注，以及设置 / 替换 / 删除、**备用密钥**；可添加新引用、按「只看有绑定的」过滤。下方两张卡：**模型清单**——「刷新模型清单」把 OpenRouter 最新目录同步进路由；**dsh 默认模型**——选路由再选模型。dsh 设置里有同名分区，两边写的是同一处。

**我们做了什么**

- 引用列表自动汇总，新路由或新插件出现即自动列出；密钥值从不回显。
- 备用密钥：一个引用可以存多把，一键切换，被换下的自动留作备用。
- 默认模型写入前校验路由清单，避免写进一个不存在的 id。

### 图 11 · 记忆与上下文

![记忆与上下文](docs/screenshots/2026-09/11-launcher-memory.webp)

**功能**

三个分页。**会话上下文**：每个会话（打开与否都行）的上下文占用与压缩阈值、**当前生效的压缩摘要（可编辑）**、压缩历史、「立即压缩」「存入长期记忆」。**长期记忆**：摘要 / 事实 / 笔记条目，搜索、钉住、改范围、编辑、删除、导入导出。**设置**：自动存摘要、自动抽取事实、注入方式、每次注入条数、是否给模型记忆工具、可选向量召回，以及召回测试。截图时 dsh 未运行。

**我们做了什么**

本体压缩后的摘要以前只能看不能改，会话之间也没有记忆；这一页补上两件事：改摘要、跨会话记忆。详见「上下文与记忆管理」。

### 图 12 · 外观皮肤

![外观皮肤](docs/screenshots/2026-09/12-launcher-skins.webp)

**功能**

三块：**界面设置**（`default` 皮肤的明 / 暗 / 跟随系统）；**启动器皮肤**（`cyberpunk-2077` / `default` / `night-city-holo`，切换即时生效，可导入 CSS）；**前端（DSH WEB UI）皮肤**（「(无)」恢复原生 / `cyberpunk-2077` / `night-city-holo`，刷新 dsh 页面生效，可导入，「获取社区皮肤」打开市场）。截图里两端都用夜之城全息皮肤。

**我们做了什么**

- 社区皮肤市场把 npm 上的皮肤包转换成本地 CSS，之后像自制皮肤一样切换、删除，不会混进插件系统。
- 内置 `night-city-holo`（石墨底、全息青细线、2077 金激活态）与 `cyberpunk-2077`（霓虹黄 × 电青）。

### 图 13 · 内部日志

## 02 · dsh 本体里的界面

### 图 14 · 消息编辑

*dsh-chat-editor · 原创*

![消息编辑](docs/screenshots/2026-09/14-dsh-chat-editor.webp)

**功能**

### 图 21 · 设置 → 联网搜索（全局）

*dsh-web-search-plus · 原创*

![设置 → 联网搜索（全局）](docs/screenshots/2026-09/21-dsh-settings-web-search.webp)

**功能**

全局配一次（启动器控制甲板的「联网搜索」分页是同一份配置）。**方式**：关闭 / 让模型自己决定 / 按触发词自动搜索 / 走 API 供应商的搜索。**搜索来源**：SearXNG（截图里是自建实例）、Serper、SerpApi、Tavily、Brave、DeepSeek 官方。**打开正文**：搜到结果后再打开前 N 条网页把正文一并交给模型。**网页读取 web_fetch** 开关：让模型读取公网网页的整页内容。下方「保存」「测试搜索」，以及只读的「已保存凭据」卡。

- 「打开正文」省掉一次工具往返；正文抽取可选接本地 trafilatura。
- 密钥经 dsh 凭据库保存；「测试搜索」直接看结果与耗时。

## 03 · 截图里看不到的部分

有些能力没有自己的面板，或者面板只露出一角。这里按用途补齐。

### 安全

- **危险命令拦截**（`dsh-safe-guard`，原创）：`rm -rf /`、无 lease 的 `git push --force`、裸设备写入、`mkfs`、Windows 盘符根删除 / 格式化、fork 炸弹等直接拦下，不打扰正常确认流；在控制甲板「安全规则」里可以加自己的**拒绝**、**需确认**（弹审批）、**自动放行**正则，改完 1.5 秒生效。
- **密钥进系统钥匙串**（`dsh-credentials-keyring`，原创）：API Key 存进 Windows 凭据管理器而不是明文文件；环境变量仍然优先；钥匙串出问题时只会读不到，不会丢密钥。
- **手机远程的局域网围栏**（`dsh-lan-fence`，原创）：开了手机扫码远程后，未配对的局域网设备访问 dsh 的 `/api` 一律 403，配对通道不受影响；纯插件实现，升级本体不会重开这个口子。
- **只本机可用**：启动器只监听 127.0.0.1，每个请求都要带令牌；套件所有能写配置的接口都拒绝跨站请求和外来 Host。

### 对话

- **临时对话**（`dsh-temp-chat`，原创）：侧栏一个按钮开一个不属于任何项目的对话，放在共用的「临时对话」工作区，用纯聊天预设（不能动文件和终端）；不会自动删除，想清理时一键删目录。
- **拖文件**（`dsh-drop-files`，原创）：把任意非图片文件拖进对话区，文件存进当前工作区的 `.dsh-uploads/`，输入框自动写入 `@.dsh-uploads/<名>`，模型用文件工具读；单个文件最多 25 MB；PDF / Office / 压缩包会存下来但模型读不出内容，拖入时会提示。
- **皮肤工坊**（`dsh-skin-studio` + Skill `skin-studio`，原创）：在对话里让模型给启动器或 dsh 做皮肤，它会先问风格、主色、明暗、背景图，写好直接落盘启用；没有图且模型不能生图时会向你要图，不会瞎编。
- **模型悬停价格**（`dsh-price-hint`，原创）：模型选择器里悬停任意模型，显示输入 / 输出 / 缓存每百万 tokens 的价格。
- **快建工作区**（`dsh-quick-workspace`，原创）：启动器仪表盘输入路径一键新建工作区（目录不存在会创建）。
- **前端皮肤注入**（`dsh-skin-loader`，原创）：把启动器里选的前端皮肤套到 dsh 网页上。

### 本体自带、默认不开的能力（上游包，我们挂上了）

| 能力 | 作用 |
|---|---|
| 持久终端（`dsh-terminal` 三件） | 模型可以开一个持久的 PTY 终端，交互式发命令、读输出、发信号，配合后台作业 |
| 定时提醒（`dsh-schedule`） | 按时间点或固定频率提醒 agent |
| LSP 代码智能（`dsh-lsp` 三件） | 配了 TypeScript 语言服务器，模型可以跳转定义、查引用、看类型 |
| MCP 客户端 + 参考记忆服务器 | 官方示例接法的知识图谱记忆（实体 / 关系 / 观察），与套件的记忆插件是两套独立机制 |
| Claude Code / Codex hook 桥 | 直接复用 Claude Code、Codex 格式的 hooks.json |

## 04 · 上下文与记忆管理

对应启动器的「记忆与上下文」页和 `dsh-memory-lite` 插件。这一章讲：dsh 自己是怎么管上下文的、哪些东西会进上下文、你能在哪里控制它们、记忆是怎么记又怎么用的。

### 1. dsh 自己是怎么做的

- 对话历史只追加、不截断。快到上限时（上下文窗口的 80%），dsh 自动把最旧的一段历史压成一段摘要，模型之后看到的是摘要而不是原文；`/compact` 命令可以手动触发。
- 上限由每个模型的 `contextWindow` 决定，默认 262,144；本地模型往往装不了这么多，要在启动器「模型参数」页按模型改成真实值，压缩才会在正确的位置发生。
- 本体原生没有跨会话的记忆：换一个会话，模型什么都不记得。

### 2. 哪些东西会进上下文，在哪里调

| 会进上下文的内容 | 来自 | 在哪里调 | 默认预算 |
|---|---|---|---|
| 系统提示词条目 | 控制甲板「提示词」 | 控制甲板 | 按条目顺序 |
| 世界书命中的设定、user 前置提示 | 控制甲板「世界书 / 提示词」 | 控制甲板 | 8000 字符，扫描最近 6 条 |
| 搜索结果（触发词模式） | 联网搜索 | dsh 设置「联网搜索（全局）」 | 可设字符预算，最多打开 5 个网页 |
| 网页正文（工具模式「打开正文」、`web_fetch`） | 联网搜索 | 同上 | 每页 2000 字符（可调）；整页读取上限 200,000 字符 |
| 记忆召回 | 记忆与上下文 | 启动器「记忆与上下文 → 设置」 | 4000 字符，最多 5 条 |
| 图片的文字描述（非视觉模型） | 图片理解 | dsh 设置 → 插件 → 图片理解 | 4 MP / 20 MB 以内的图 |
| 工具定义 | 本体与各插件注册的工具 | 控制甲板「工具开关」；临时对话默认屏蔽全部工具 | 截图里约 94 项、17.6k tokens |

这几处注入都是**作为单独一条上下文放在你的消息之后**，你的原话不会被改写。想看效果：输入框旁的上下文环、会话的「上下文」分页（社区插件 `dsh-context`）、启动器记忆页的压力条。

```mermaid
flowchart TB
  U["你的消息"] --> REQ["发给模型的请求（附带注入：世界书 · 搜索结果 · 记忆召回）"]
  REQ --> LOG[("会话历史（只追加）")]
  LOG -- "接近上限" --> CMP["自动压缩成摘要"]
  CMP -- "摘要自动存入" --> MEM[("记忆库：摘要 / 事实 / 笔记")]
  LOG -- "每 8 轮抽取事实" --> MEM
  MEM -- "按相关度召回" --> REQ
  EDIT["启动器：改当前摘要"] --> LOG
  CE["消息编辑：改 / 删"] --> LOG
  CE -- "相关记忆失效" --> MEM
```

### 3. 会话上下文分页：看和改压缩摘要

- **看**：每个会话（打开与否都行）的上下文占用与压缩阈值、当前生效的摘要、压缩历史。
- **改**：直接编辑摘要文字，保存后下一次请求起模型就按你的文字继续；原文仍在会话日志里，随时可追溯。
- **立即压缩**：不等到阈值，现在就压。**存入长期记忆**：把当前摘要存成一条记忆。
- 什么时候不能改：会话正在回答、正在压缩、或这段摘要已经被更新的压缩替代。

### 4. 长期记忆分页：跨会话记住东西

**记什么。** 三类条目：
- **摘要**——每次自动压缩产生的摘要自动存一份（每个会话留最新的）；
- **事实**——每 8 轮对话，由会话自己用的模型抽取一次"值得长期记住的事"（可关掉，也可改间隔）；
- **笔记**——你在页面上手写，或模型通过 `memory_note` 工具写。

每条有范围：**全局**（关于你的）或**仅此工作区**（关于某个项目的）；可以钉住、编辑、删除、导入导出、一键清空未钉住的。

**怎么用。** 新会话第一轮，钉住的和相关的条目会作为一条上下文放在你的消息之后；之后每一轮只补充还没注入过的相关条目。注入方式可选「首轮钉住 + 相关 / 只首轮 / 不注入」，每次最多几条、总字数多少都可调。召回按关键词匹配（支持中文），也可以接本地向量接口（LM Studio / Ollama）做语义召回；设置页有「召回测试」，输一句话就能看到会注入什么。模型侧还有 `memory_recall` / `memory_note` 两个工具，可关。

**改了源对话之后。** 用消息编辑改了或删了某条消息，从它抽出来的事实和摘要会失效：留在记忆页里加标签供你检查，不再自动召回；如果已经注入到别的会话，那些会话下一步会收到一条撤回或更正提示。在记忆页把一条文本保存一次，等于确认它，重新生效。

### 5. 文件在哪

- 设置：`~/.dsh/memory-lite.json`（是否启用、自动存摘要、自动抽取事实、抽取间隔、注入方式、每次条数、字数预算、是否给模型工具、向量接口）。
- 数据：`~/.dsh/memory/memory.json`（条目）与 `vectors.json`（可选向量）。
- 两者都在启动器「存储空间」的配置备份里；恢复后 dsh 运行中也会合并进来。

### 6. 常见问题

**会多花模型调用吗？** 只有事实抽取（每 8 轮一次短请求，用会话自己的模型，可关）和你手动点的「立即压缩」；召回和注入都在本地完成。

**改了摘要，原文还在吗？** 在。改摘要是追加一条新记录，原文留在会话日志里；「上下文」分页的事件列表能看到这次编辑。

**记忆会把别的项目的东西带进来吗？** 事实分全局 / 工作区两档，工作区范围只在同一目录召回；非首轮有相关性门槛；总注入量有预算；用「召回测试」可以提前看。
